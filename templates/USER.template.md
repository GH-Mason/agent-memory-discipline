# USER.template.md — starter user-profile file

> The user profile is a **hand-maintained** store. Automation may read it,
> never write it. A deleted preference is something the user will rarely
> re-state, so the deletion is usually permanent in practice.
>
> Suggested budget: see docs/operations.md §1 (single source for all numbers).
> Keep entries stable, specific, and
> phrased as facts about the user — not as instructions to the agent.

<!-- ── identity ──────────────────────────────────────────────────────── -->
<Role, context, languages, time zone. Only what the agent genuinely needs
every session. No document numbers, no addresses, no credentials — ever.>
§
<!-- ── communication preferences ─────────────────────────────────────── -->
<How the user wants to receive information: length, language, formatting,
channel differences (e.g. "short on mobile, fuller on desktop").>
§
<!-- ── decision preferences ──────────────────────────────────────────── -->
<How the user wants decisions made: what to decide autonomously, what to
escalate. Stated once — this class of preference is high-value and stable.>
§
<!-- ── workflow preferences ──────────────────────────────────────────── -->
<Working conventions: how deliverables are handed over, naming, what kinds
of actions require approval first.>
§
<!-- ── recurring corrections (the highest-value class) ───────────────── -->
<Things the user has corrected before. These are the entries most likely to
prevent repeated friction — and the ones automation must never touch.>
